## 一、项目定位

### 1.1 项目目标

CMCI 旨在建立一套独立的加密资产市场周期研究体系，系统研究全球宏观金融环境、Crypto 内生供需、资本配置与传导机制，以及这些因素与市场价格表现之间的关系。

项目最终希望回答：

- 当前全球宏观金融环境处于什么状态？
- 全球资本环境如何影响 Crypto 市场？
- BTC 的内生供给机制与需求结构是否仍然构成重要周期驱动力？
- Crypto 市场的资本供给、需求强度、持仓结构和内部轮动发生了什么变化？
- 历史上是否存在可重复识别的大周期阶段？
- 市场周期正在稳定运行，还是已经出现转换迹象？
- 当前判断的证据强度、数据质量和风险状态如何？
- 这些研究结果能否为不同交易策略提供有价值的环境信息？

### 1.2 项目边界

CMCI 是独立的研究与环境认知系统，不是交易策略本身。

它与 MTPS、MRE、网格策略等系统的关系是：

- CMCI 研究宏观环境、周期状态、资本环境和风险背景。
- 具体策略负责自己的入场、出场、仓位、止损和交易执行。
- CMCI 可以提供环境约束、风险提示和策略适用性参考。
- CMCI 不直接生成买入、卖出、开仓或平仓指令。
- 策略不得将 CMCI 的某个单一状态标签当作唯一交易依据。

### 1.3 研究原则

- 假说优先于结论： 不预设减半周期、宏观流动性或机构资金中的任何一项必然主导市场。
- 数据优先于叙事： 不以事后解释代替可复现检验。
- 区分相关与因果： 价格相关性不等于资本迁移，领先关系不等于因果关系。
- 重视时间真实性： 历史研究只能使用当时已经可获得的数据版本。
- 防止循环论证： 驱动力识别、市场结果检验和周期状态输出必须进行用途隔离。
- 允许否定： 研究结论可以是成立、不成立或证据不足。
- 版本化： 数据、研究方法、模型和历史判断均须保留版本。
- 控制研究范围： 新增指标和数据源必须说明独立研究价值，不能以扩大数据量代替研究进展。

## 二、总体研究架构：L1–L6 六层模型

### L1：外部宏观与全球金融环境

研究 Crypto 市场之外的宏观金融环境。

主要内容：

- 全球流动性与主要央行资产负债表
- 货币政策、政策利率和实际利率
- 美元指数及主要汇率
- 国债收益率曲线
- 信用利差与金融条件指数
- VIX 等风险偏好指标
- 全球经济周期与金融压力
- 传统金融市场的估值与风险环境

L1 研究的是外部环境，不直接等同于 Crypto 的实际资金流入。

### L2：Crypto/BTC 内生供给机制

研究 Crypto 市场自身的供给机制，重点关注 BTC。

主要内容：

- BTC 减半事件及发行变化
- 新增供给与流通供给
- 矿工收入、成本、抛售与储备
- 长期持有者和短期持有者供给
- 交易所可用供给
- 链上供给分布及结构变化

特别约束： BTC 减半是协议确定的供给事件，但“四年价格周期”只是需要检验的历史假说。不能因为减半事件按约四年发生，就预先认定价格也必然遵循四年周期。

### L3：Crypto 需求侧驱动力

研究谁在购买 Crypto、为什么购买、购买意愿如何变化。

主要内容：

- 个人投资者与机构投资者需求
- ETF/ETP 投资需求
- 机构配置意愿与配置比例变化
- 稳定币持有与使用需求
- 不同资产类别的风险偏好
- Crypto 应用、支付和金融活动需求
- 参与者结构与需求持续性

L3 研究的是需求及其驱动力，不应把需求意愿直接等同于已经发生的资金流入。

### L4：资本传导机制

研究需求如何转化为实际资金流，以及资金如何进入、离开或在 Crypto 内部流动。

主要内容：

- BTC/ETH ETF 和 ETP 净流入
- 稳定币发行、赎回与供应变化
- 交易所净流入与净流出
- 机构资金配置与持仓变化
- 现货与衍生品资金变化
- 跨市场资金渠道
- 资金流入后的持续性、留存率和反转情况

L4 是连接需求与市场表现的重要层，但资金流数据必须关注统计口径、来源覆盖和实际可观察程度。

### L5：市场表现观测层

L5 是可观测的市场行为和结果数据。

主要内容：

- BTC、ETH 和主要 Crypto 资产价格
- 趋势、涨跌幅与收益率
- 成交量、成交额和交易活跃度
- 波动率与回撤
- 市场广度
- BTC Dominance
- BTC、ETH、Altcoin 的内部轮动
- 现货与衍生品市场行为
- 资金费率、未平仓合约和清算数据

L5 具有双重角色：

- 作为未来 L6 周期状态识别的观测输入。
- 作为检验 L1–L4 驱动力解释能力的结果观测对象。

这两个用途必须隔离，不能因为同一批数据既参与模型识别，又被用于证明模型正确，而形成循环论证。

### L6：周期状态输出层

L6 是模型研究和推断的产物，不是原始数据层。

未来可能输出：

- 大周期阶段
- 阶段成熟度
- 周期转换状态
- 市场风险状态
- 证据强度与模型置信度
- CCE 多维资本环境
- 数据质量与适用性状态

硬规则： L6 不得反向参与 L1–L4 驱动力识别。 L6 只能作为研究结果或策略环境接口，不得被用来证明产生它的驱动力假说。

第一阶段不开发 L6。

## 三、数据隔离与防循环论证硬规则

### 3.1 L5 数据三分区

L5 数据按用途划分为：

- training：用于模型训练或参数估计。
- identification：用于驱动力识别、关系检验和模型选择。
- validation：用于独立验证和最终评价。

每条 L5 指标记录必须具备 usage_partition 字段，明确其用途分区。

如果某条指标在不同研究中承担不同用途，应建立独立的数据用途登记或数据集版本，不得在同一研究任务中模糊混用。

### 3.2 七条强制规则

1. 同一研究任务中，同一时间窗口、同一指标的数据不得同时进入识别区和验证区。
2. L5 用于检验 L1–L4 时，不得复用 L6 周期识别所使用的同一窗口。
3. 不得用 L5 识别出的阶段标签，再解释同一窗口的 L5 市场表现。
4. 正式验证区一旦用于最终评价，不得因结果不理想而反复调参后仍称其为独立验证集。
5. 对相邻窗口、重叠窗口和存在时间依赖的样本，必须设置适当隔离期（embargo），避免信息泄漏。
6. 滚动或扩展窗口研究必须保存每次实验的时间边界、数据版本、特征版本、模型版本和实验参数。
7. L5 的训练、识别和验证用途必须在数据登记阶段明确，不能等模型开发完成后再追溯性地解释分区。

### 3.3 L6 隔离规则

- L6 不参与 L1–L4 驱动力识别。
- L6 的历史阶段标签不得作为未经隔离的训练标签，反过来证明产生该标签的同一组指标有效。
- 历史事后研究标签与实时模型推断结果必须分开存储。
- 任何使用历史阶段标签的研究，必须说明标签来源、形成时间、是否事后确认及其独立性。

## 四、层间关系：研究假设而非预设因果

| 关系 | 研究问题 |
| --- | --- |
| L1 → L3 | 全球金融条件是否影响 Crypto 需求意愿？ |
| L1 → L4 | 全球流动性、美元和利率是否影响 Crypto 资金传导？ |
| L2 → L4 | 发行变化和矿工行为是否影响可流通供给与资金流？ |
| L3 → L4 | 需求意愿是否通过 ETF、现货、稳定币等渠道转化为资金流？ |
| L4 → L5 | 资金流是否影响价格、成交量、市场广度与波动率？ |
| L5 → L3/L4 | 价格变化是否反过来影响信心、需求和资金流？ |

以上箭头均为待检验的领先滞后假设，不代表已经证实的因果关系。

不同层的数据频率不同，必须研究：

- 混频数据对齐
- 数据发布时间和可用时间
- 领先滞后关系
- 频率转换造成的信息损失
- 反馈回路与内生性

不预设固定领先周期，具体时间尺度由研究结果决定。

## 五、CCE：Crypto Capital Environment

### 5.1 定位

CCE 是基于 L3、L4 为主，结合 L1 环境条件形成的综合认知层。

CCE：

- 不是独立数据源。
- 不是第七层驱动力。
- 不重复建设一套与 L1–L5 平行的数据体系。
- 不在第一阶段强行生成单一总分。

### 5.2 四个主要维度

- 资本供给： 通过 ETF、稳定币、交易所、机构等渠道实际进入或离开 Crypto 的资金。
- 需求强度： 参与者购买意愿、配置需求和需求持续性。
- 持仓结构： 长期/短期、机构/散户、现货/杠杆等结构。
- 内部轮动： BTC、ETH、Altcoin 之间的相对资金与市场行为变化。

内部轮动研究必须控制全球流动性环境，避免把宏观驱动的整体市场 Beta 误判为 Crypto 内部轮动。

### 5.3 资本质量：跨维度评价项

资本质量不是第五个并列维度，也不能未经验证就作为一个总乘数修正其他维度。

对每个资金流或持仓渠道，至少考察：

- 现货资金占比
- 杠杆资金占比和衍生品依赖程度
- 资金持续性：滚动净流入连续性、留存率、反转率
- 资金集中度：头部渠道或主体占比
- 脆弱性：杠杆拥挤、清算敏感度、资金费率和 OI 极端程度

处理方法：

- 保留各子指标原始值。
- 按历史分布进行标准化，并记录标准化窗口与版本。
- 分别观察绝对水平、变化速度和持续时间。
- 对不同资本供给、需求、持仓和轮动维度附加质量标记或置信度修正。
- 先输出可解释的质量向量或高/中/低/未知分档。
- 数据缺失时输出 unknown，不得默认高质量或低质量。
- 只有经过独立样本验证，证明质量指标具有增量解释能力后，才考虑加权合成。

## 六、核心竞争性假说

CMCI 不预设哪一种假说正确。

- 假说 A：BTC 内生供给仍是重要周期驱动力
  - 减半、矿工供给和长期持有者行为仍然对大周期具有重要解释力。
- 假说 B：宏观流动性与需求侧解释力增强
  - 全球金融条件、机构配置和资本传导机制，对 Crypto 周期的解释力可能已经超过单纯的供给事件。
- 假说 C：驱动力具有阶段性和环境依赖性
  - 不同市场阶段、不同宏观环境下，主导驱动力可能发生变化。

### 检验路径

- 比较 L1、L2、L3、L4 对 L5 市场表现的边际解释力。
- 使用滚动或扩展窗口，检查解释力与样本外预测误差贡献是否随时间变化。
- 使用结构变点方法，检查驱动力与市场结果之间的关系是否改变。
- 统一变量口径，进行标准化、控制变量、稳定性和稳健性检验。
- 比较样本外预测增益，而不是只比较回归系数大小。
- 报告有效独立样本量，不把数百个滚动窗口误称为数百个独立宏观周期。
- 允许最终结论为无法判断或证据不足。

## 七、第一阶段：只做三件硬事

第一阶段不追求完成整个 CMCI，而是建立可靠的数据基础和历史研究基础。

### 任务一：L1–L5 数据底表与数据治理

目标：

建立覆盖 L1–L5 的统一指标字典、数据源登记、原始数据、标准化数据和历史可用性回放机制。

最低验收标准：

- 数据字典覆盖 L1–L5 全部候选指标。
- 每个指标至少具备：
  - observation_period
  - release_time
  - available_time
  - vintage_time
  - value
  - source
- 记录数据频率、单位、时区、缺失率、更新方式、修订机制、授权与来源说明。
- L5 指标强制登记 usage_partition。
- 至少完成一次按 available_time 还原的完整历史回放。
- 证明历史时点只使用当时已经可获得的数据版本。
- 宏观数据优先使用 vintage 数据或可追溯历史版本，不得用最终修订值冒充当时可用值。
- 完成独立前视偏差审计。

### 任务二：全球金融与 Crypto 关系研究

研究必须区分三类关系：

- 共同驱动： 股票与 BTC 同涨同跌，可能是共同宏观因素驱动。
- 资本竞争/替代： 边际风险资本在传统资产与 Crypto 之间的配置偏好发生变化。
- 资金传导： 宏观条件通过 ETF、稳定币、机构配置、交易所资金等具体渠道传导至 Crypto。

最低验收标准：

- 每类关系至少给出一个可复现的检验方法。
- 每类关系给出“成立 / 不成立 / 证据不足”的结论档位。
- 进行领先滞后检验和稳健性分析。
- 报告样本范围、数据限制和识别局限。
- 不得仅凭价格相关性推断资金迁移。
- 相对吸引力优先使用配置比例变化、资金流、估值差、风险调整后预期等前瞻或结构性指标。
- 已实现相对涨跌幅只能作为结果变量或描述变量，不能直接作为预测周期的原因。
- 即使前瞻指标也可能内生，必须说明识别限制。

### 任务三：BTC 大周期历史底表

目标：

建立覆盖所有可用 BTC 减半周期和减半事件的结构化历史资料。

至少包括四类字段：

- 事件字段：减半时间、区块高度、发行变化等。
- 区间字段：周期区间、价格表现、回撤、波动和关键时间点。
- 宏观字段：利率、美元、全球流动性、金融压力等。
- 市场结构字段：机构参与、ETF、衍生品、稳定币和市场参与者结构等。

最低验收标准：

- 覆盖所有可用 BTC 减半事件与对应历史区间。
- 明确区分减半事件和四年价格周期假说。
- 完成有效样本扩充可行性评估。
- 报告有效独立宏观周期样本数量及外推限制。

样本扩充必须分别评估：

- BTC 多时间尺度数据： 可以补充周期内部行为样本，不能伪造独立宏观周期数量。
- ETH 等跨资产： 可以检验部分市场行为机制的可迁移性，不能直接等同 BTC 减半周期。
- 其他有减半机制的资产： 可以作机制类比，但制度、流动性和市场成熟度不同。
- 传统金融历史周期： 可以研究宏观金融周期与风险资产关系，不能直接当作 Crypto 周期样本。

### 任务依赖关系

任务一的数据规范完成后，任务二和任务三可以并行推进。

## 八、样本量与研究有效性

- 滚动窗口数量不等于独立宏观周期数量。
- 多时间尺度观测可以丰富周期内部样本，但不能凭此增加独立宏观周期数。
- 跨资产样本可以检验机制的可迁移性，但必须报告制度差异。
- 每项研究报告必须显式声明有效独立样本数量的估算方法，并在同一研究中保持口径一致。
- 应分别报告原始观测数量、去相关后的有效观测数量、独立宏观周期或事件数量。
- 当样本不足以支持统计推断时，应明确标记为探索性研究，不得用高频数据量制造确定性。

有效样本估算方法可根据研究对象采用周期/事件聚类、序列相关修正后的有效样本量、区块自助法或其他适当方法，但必须说明选择依据、假设和局限。

## 九、数据治理与前视偏差控制

### 9.1 时间字段

所有时间敏感数据必须区分：

- observation_period：数据描述的实际观察区间。
- release_time：数据发布的时间。
- available_time：研究系统实际能够获得该数据的时间。
- vintage_time：数据版本或修订版本的时间。
- value：具体数值。
- source：数据来源。

同时登记：

- 数据频率
- 单位
- 时区
- 数据来源与授权说明
- 更新方式
- 修订机制
- 缺失率
- 质量状态

### 9.2 历史数据回放

历史回放必须以 available_time 为准。

例如，某宏观指标描述的是一月份，但在二月份才发布，那么一月份的实时判断不能使用二月份才公布的数据。

对会修订的宏观数据：

- 优先保存 vintage 数据。
- 无法获得 vintage 数据时，必须记录限制。
- 不得把最终修订数据伪装成历史实时可用数据。

### 9.3 已知未来事件

BTC 减半等可提前确定的协议事件可以作为已知未来事件日历。

数据契约必须显式标记：

known_future_event=true

并与未来市场结果数据严格区分。已知事件日历不属于预测泄漏，但不得与未来价格、成交量等未知数据混淆。

### 9.4 独立前视偏差审计

任务一完成前，由独立于数据构建者的人员执行审计：

- 从历史时间范围中随机抽取 N 个回放时点。
- 检查每个时点实际使用的所有数据。
- 核对每项数据的 available_time、vintage_time 和数据版本。
- 检查是否存在当时尚未发布的数据、事后修订值或未来市场数据。
- 保存抽样范围、检查记录、问题清单和审计结论。

N 的取值、抽样方式和审计覆盖率应在审计方案中预先登记。审计不通过则任务一不得验收。

## 十一、周期阶段、成熟度、风险与置信度

### 11.1 阶段分类

暂不冻结具体大周期阶段数量和名称。

未来阶段分类至少满足：

- 历史上可重复识别。
- 与相邻阶段存在可检验的统计差异。
- 对至少一种实际策略具有区分价值。

小周期、内部轮动和趋势运动状态，不应被强行纳入同一套大周期固定序列。

### 11.2 阶段成熟度

成熟度不等于阶段持续时间。

候选因素：

- 持续时间
- 累计涨跌
- 趋势持久性
- 相对长期趋势的偏离
- 估值与市场参与者结构
- 动量衰竭或扩散情况

### 11.3 风险状态

风险独立于周期阶段。

候选因素：

- 杠杆拥挤
- 资金费率
- 未平仓合约
- 清算敏感度
- 流动性恶化
- 波动率极端
- 资本质量和市场结构脆弱性

高风险不等于马上下跌。

### 11.4 置信度与校准

置信度必须与阶段成熟度和风险状态分开。

可能的信息来源：

- 数据覆盖度
- 模型一致性
- 证据强度
- 历史校准情况
- 是否偏离训练分布

只有经过独立校准的概率，才可以作为概率解释。

置信度校准硬规则：

- 校准集必须独立于模型训练集。
- 校准集不得被反复用于调参后仍称为独立校准集。
- 校准方法、时间范围、数据版本和模型版本必须留档。
- 校准后的结果必须在独立验证区进行评价。
- 校准效果不合格时，只能输出证据等级或不确定性说明，不得伪装成经过校准的概率。

## 十二、周期转换与结构漂移

两者是不同课题。

### F1：周期转换检测

实时判断：

- 当前阶段是否稳定
- 是否进入转换观察状态
- 是否达到转换确认条件

不得事后回填转换确认时间。

### F2：结构漂移监测

定期检查：

- 周期规律是否变化
- 特征分布是否变化
- 驱动力关系是否变化
- 模型解释力是否下降
- 模型校准是否失效

### 漂移后的三级响应

- 参数变化： 保留阶段定义，重新估计参数。
- 模型关系变化： 驱动力关系或特征结构改变，重构部分模型。
- 阶段体系变化： 原有阶段定义不再成立，才考虑重构阶段体系。

所有响应必须版本化，保留旧版结果，不得静默改写历史。

即便只是参数重估，也必须评估历史阶段标签影响，至少记录：

- 影响日期
- 重要阶段边界变化
- 牛熊转换点变化
- 标签迁移矩阵
- 新旧版本差异

不能只用日期变动占比作为唯一判断标准。

## 十三、历史记录与版本治理

### 13.1 数据版本

原始数据、标准化数据、修订版本和研究数据集均应保留版本标识。

### 13.2 实时推断记录

所有实时推断记录必须采用 append-only 写入。

即：

- 已写入的实时判断不可原地修改。
- 数据纠错、模型修正或人工复核必须追加新记录。
- 新记录必须关联原记录，并说明修正原因。
- 必须保留修正时间、操作者/系统、数据版本和模型版本。

历史查询可以展示最新有效版本，但必须能够还原当时实际发布的原始判断。

### 13.3 研究实验版本

每次研究实验至少保存：

- 数据集版本
- 数据时间范围
- 特征版本
- 模型版本
- 参数配置
- 训练/识别/验证分区
- 实验时间
- 结果与结论
- 是否使用过正式验证集

## 十四、策略接口契约草案

第一阶段只定义接口，不实现策略接入。

### 14.1 候选输出字段

- as_of
- valid_until
- model_version
- data_quality
- coverage
- major_cycle_state
- transition_status
- maturity_state
- risk_state
- confidence 或 evidence_grade
- cce
- evidence_summary
- missing_inputs
- known_limitations
- source_snapshot_id
- revision_id
- available_time
- inference_time
- status

### 14.2 字段级时间有效性

不同字段可以采用不同更新频率，但每个字段必须独立携带：

- as_of_time
- valid_until
- data_quality
- source_snapshot_id

整体记录必须明确字段级新鲜度。

策略侧读取时：

- 各字段独立判断是否过期。
- 整体记录的有效性按各必需字段中最先失效者判定。
- 非必需字段过期时，按预先定义的降级规则处理。
- 部分字段更新，不得自动把其他旧字段标记为新鲜。
- valid_until 到期而未更新时，策略侧必须按 data_quality 降级处理，不得沿用旧判断作为正常状态。

### 14.3 更新频率

按数据和模型层级定义：

- 宏观字段：随原始数据发布和修订更新。
- 资本流动字段：按来源实际更新频率更新。
- 市场风险字段：根据数据源支持的频率更新。
- 周期状态字段：按模型规定的推断周期更新。

不得因为接口定时刷新，就把没有新增信息的旧数据包装成新判断。

### 14.4 缺失数据

不得静默填充。

必须提供 missing_inputs。

data_quality 至少支持正常、降级、不可用等状态。

不可用状态不得被策略误认为正常判断。

## 十五、第一阶段管理规则与完成判定

### 15.1 控制范围

第一阶段不允许因为不断增加指标和数据源而无限延期。

新增数据源必须说明：

- 它解决什么独立研究问题？
- 相比已有数据增加了什么独立信息？
- 缺少它会造成什么具体误判？
- 数据质量、历史覆盖和授权情况如何？
- 接入成本是否与研究价值相称？

不能回答上述问题的指标，进入候选清单，不作为第一阶段必需项。

### 15.2 第一阶段完成判定

- 三项任务分别达到最低验收标准。
- 数据字典、数据源登记和历史数据底表可供研究使用。
- 历史回放能够按 available_time 还原。
- 独立前视偏差审计通过。
- 不存在未解决的数据时间错误、历史版本混淆或前视偏差。
- 任务二、任务三的结论和限制均有可复现材料。
- 研究报告明确区分事实、假说、证据和推断。

## 十七、v0.1 的冻结与非冻结事项

### 本版本冻结

- 项目定位和研究边界
- L1–L6 总体架构
- L5 三分区与防循环论证规则

### 本版本不冻结

- 最终周期阶段数量与名称
- 哪一种驱动力占主导
- CCE 的最终合成算法
- 资本质量的最终权重
- 置信度最终模型
- 周期转换检测算法
- 结构漂移算法
- 具体策略如何使用 CMCI 输出

最终原则：冻结研究边界与方法，不冻结研究结论。

CMCI 第一阶段正式启动，优先建设 L1–L5 数据字典、指标底表和数据治理基础设施。
